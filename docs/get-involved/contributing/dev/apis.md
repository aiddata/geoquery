# APIs

Everything is Django REST Framework, wired in `backend/geoquery/urls.py`. Add an endpoint as a view in the app that owns the behaviour, in that app's `urls.py`, with a serializer for its response.

| Prefix | What | Audience |
|---|---|---|
| `/api/features/`, `/api/datasets/`, `/api/analytics/`, `/api/visualize/` | Internal API | The frontend only; may change at any time |
| `/api/_allauth/`, `/api/auth/`, `/api/accounts/` | Authentication (django-allauth) | The frontend |
| `/api/idp/` | GeoQuery's OpenID Connect provider | The MCP server |
| `/api/config/` | Runtime config: the caller's beta features, the basemap key | The frontend |
| `/api/stats/` | The stats snapshot and live status | The `/stats` page |
| `/api/public/v1/` | Public API | Anyone; versioned and documented |
| `/api/stac/v1/` | STAC API | STAC clients; versioned and documented |
| `/mcp` (port 8001) | MCP server | AI assistants |

## Internal API

| Path | Purpose |
|---|---|
| `features/autocomplete/`, `ids/`, `intersecting/`, `presets/` | Boundary search, feature ids for a set, sets intersecting an area, boundary presets |
| `features/tiles/<fc>/<z>/<x>/<y>.mvt`, `multitiles/…` | Vector tiles for one or several boundary sets, from PostGIS `ST_AsMVT` |
| `datasets/`, `datasets/<name>/`, `datasets/categories/`, `datasets/coverage/` | The catalog, one dataset, categories, and which datasets cover a selection (`POST`, since selections are large) |
| `analytics/requests/` | Submit a request (`POST`; throttled `request_submit`) |
| `analytics/requests/<uuid>/`, `…/recipe/` | A request's page data, and its recipe, which **Duplicate request** saves as a share link |
| `analytics/shares/`, `shares/<id>/` | Create a share link, and open one ([below](#share-links-and-recipes)) |
| `analytics/request-token/`, `history/<token>/`, `my-requests/` | Emailed request-history links, and a signed-in user's requests |
| `analytics/legacy-requests/…`, `legacy-history/<token>/` | Requests from the previous GeoQuery |
| `visualize/…` | The beta map and notebook export |

Request pages are open to anyone with the request's UUID: the UUID is the secret.

### Share links and recipes

A **recipe** is a versioned description of a request's boundaries and datasets, without its name or email: `{v: 1, boundaries: {fcIds, featureIds}, datasets: [...]}`. The frontend builds them (`lib/recipe.ts`), and so does `analytics/recipe.py` from a past request's `data`.

- `GET requests/<uuid>/recipe/` builds a past request's recipe and checks it against today's catalog, listing anything that no longer applies (`dropped`). Requests with an uploaded boundary return 409.
- `POST shares/` normalizes a recipe and stores it in `shared_recipes`, keyed by a 10-character base62 hash of its canonical JSON, so the same request always gets the same link. A clash with a different recipe moves to 16 characters. Recipes are capped at 200 KB, and creation is throttled (`share_create`). Links never expire.
- `GET shares/<id>/` returns the recipe, checked the same way as a past request's.

## Authentication

Sign-in is django-allauth in headless mode (`HEADLESS_ONLY`): the frontend talks to `/api/_allauth/` and renders every page itself. GitHub is the only provider, and email addresses must be verified. `/api/auth/csrf/` sets the CSRF cookie the SPA needs.

GeoQuery is also an OpenID Connect provider (`allauth.idp`, at `/api/idp/`). The MCP server signs users in through it, so an assistant acts as the same `accounts.User` the website would, with the same catalog access ([Configuration › MCP server](configuration.md#mcp-server)).

## Public API

`backend/public_api/`, at `/api/public/v1/`: datasets, boundary sets, presets, coverage and stats. The user-facing overview is [API access](../../../using-geoquery/api.md); the reference is generated by drf-spectacular at `docs/` (Swagger UI) and `schema/`.

Every view mixes in `PublicApiBaseMixin` (`public_api/base.py`), which supplies:

- **Authentication:** `PublicApiKeyAuthentication` reads `Authorization: Api-Key <key>`, but `resolve_api_key` is a stub that always returns no consumer, so everyone is anonymous during the beta. Swapping in a real lookup is the only change needed to turn keys on.
- **Throttling:** `PublicApiThrottle`, per address at `public_api_anon`, or by a consumer's tier once keys exist.
- **Errors:** a stable `{"error": {"code", "message"}}` envelope, for these views only.

To add an endpoint:

1. Write a serializer for its response. Never return a model serializer used internally: the public shape must not change when the app does.
2. Add the view with `PublicApiBaseMixin` and `@extend_schema` for anything drf-spectacular can't infer.
3. Add it to `api_urlpatterns` in `public_api/urls.py`. Only those routes go into the schema. Order matters where a literal path shares a prefix with `<str:name>/`.
4. Add the path to `EXPECTED_PATHS` in `public_api/tests/test_schema.py`, and tests of its own.

### Stats endpoints

`stats/`, `stats/timeseries/` and `stats/status/` (`public_api/stats.py`) publish the `/stats` page's figures in their own fixed shape, read from the hourly snapshot (`stats/builder.py`). They return 503 if no snapshot exists yet, rather than the slow live build the internal endpoint falls back to.

Unlike the rest of the public API, they send `Access-Control-Allow-Origin: *`, so other sites can read them from the browser. That means excluding their paths from corsheaders in `CORS_URLS_REGEX`: corsheaders would otherwise answer a cross-origin preflight itself, without the header.

## STAC API

`backend/stac_api/`, at `/api/stac/v1/`: each dataset is a STAC collection and each of its resources an item. It conforms to STAC API Core, Collections and OGC API Features, with item search. It has its own mixin (`StacApiBaseMixin`): no authentication, a `stac_api_anon` throttle, and a wildcard CORS header, with its paths likewise excluded from corsheaders.

## MCP server

`backend/mcp_server/`, run by `manage.py run_mcp` (FastMCP, streamable HTTP). It lets AI assistants search GeoQuery, read already-extracted data, draw maps and submit requests.

| Tools | Purpose |
|---|---|
| `search_boundaries`, `get_boundary`, `search_datasets`, `get_dataset`, `list_available_data` | Find boundary sets and datasets, and what's already extracted for them |
| `get_data`, `show_map` | Read extracted values (CSV in the text, plus structured content), and render an interactive choropleth |
| `preview_request`, `submit_request`, `get_request_status`, `list_my_requests` | Exports. Submitting asks the user to confirm, and is capped at `MCP_SUBMIT_MAX_TASKS` |
| `get_citations`, `get_guide` | Citations for the data used, and longer guides (`mcp_server/guides/`) |

There are also prompts (`explore_place`, `summarize_request`, `cite_sources`). Every result that carries data includes an `attribution` object; `report_missing_attribution` lists datasets and boundary sets missing a license or citation.

The map `show_map` renders is a separate single-file app in `frontend/mcp-map/`. `bun run build:mcp-map` writes it into `backend/mcp_server/apps/static/`, where the server serves it as an MCP app resource.

In the cluster, the nginx proxy sends `/mcp` and the OAuth paths (`/authorize`, `/token`, `/register`, `/.well-known/…`) to the MCP server.
